## 1. Задача в одном предложении

Извлечь из `.rodata` прошивки **все строковые таблицы допустимых значений** для
команд камеры и собрать карту «команда → какие значения она принимает».

## 2. Зачем

Камера принимает команды вида `{"command":"RCISOSet","ISO":"200"}`. Значения —
строки (`"200"`, `"4:3"`, `"MF"`, `"FHD_24"`).

**Вчера мы случайно, ища `4K_*`, нашли семь видеоформатов — и среди них `4K_24` и
`FHD_24`, то есть 24p, которого НЕТ ни в одном меню камеры и который никогда не
поддерживало официальное приложение.** Проверено на живой камере: работает.

**Отсюда мысль этой задачи:** если случайный поиск дал скрытый режим, то
систематический может дать ещё. Нужна полная карта, а не выборочные находки.

## 3. Входные данные

```
research/YI-M1-firmware-3.2-int/3.2-int/firmware.bin.0.03127296.decompressed
```

Это блок `.rodata`. **Он загружается в RAM по базовому адресу `0x0043f800`.**
Пересчёт всегда такой:

```python
BASE = 0x0043f800
offset_in_file = ram_address - BASE
ram_address     = offset_in_file + BASE
```

Также доступен `.text`: `...0.00008192.decompressed`, база `0x00002000` — но
строки лежат в `.rodata`, он тебе, скорее всего, не понадобится.

### Что уже известно (данность, перепроверять не надо)

**Пул ключей параметров** — непрерывная область, строки с завершающим нулём:

```
0x6b835c  path            0x6b83c5  EV
0x6b8361  name            0x6b83c8  ISO
0x6b8366  MeteringMode    0x6b83cc  ColorMode
0x6b8373  FocusMode       0x6b83d6  DialMode
0x6b837d  ImageQuality    0x6b83ee  FFrame
0x6b838a  ImageAspect     0x6b840f  Cnt
0x6b8396  FileFormat      0x6b8416  Resolution
0x6b83a1  DriveMode       0x6b8421  Vol
0x6b83ab  Fnumber
0x6b83b7  dShutterSpeed
```

**Найденные значения видеоформата** (все семь приняты живой камерой):
```
0x6b8a50  4K_30      0x6b8cf0  FHD_60
0x6b8a56  4K_24      0x6b8cf7  FHD_30
0x6b8a5c  2K_30      0x6b8cfe  FHD_24
0x6b8d1b  4K_30_LOW
```

**Важное наблюдение о раскладке:** строки в пуле **перемешаны и, похоже,
сгруппированы по ДЛИНЕ, а не по смыслу.** Рядом с `4K_30` лежат `Vivid`, `Scene`,
`Sunny`, `Spot`, `S-AF`, `C-AF`, `MF`, `16:9` — то есть значения РАЗНЫХ команд
вперемешку. Это типичный дедуплицирующий пул компилятора.

**Из этого следует: нельзя определять принадлежность значения к команде по
соседству в памяти.** Соседство — не доказательство. Учитывай это.

## 4. Что сделать

### Шаг 1 — Полный дамп строк
Извлеки **все** печатаемые ASCII-строки длиной ≥ 2, завершённые нулём, из
`.rodata`. Для каждой запиши: **RAM-адрес**, длину, содержимое.
Сохрани полный дамп в `agent-tasks/work/task05/all_strings.txt` (он останется в
песочнице, в отчёт целиком не тащи).

Сколько всего получилось — напиши в отчёте.

### Шаг 2 — Найти границы «пула значений»
Пул ключей мы локализовали (`0x6b835c`–`0x6b8421`). Определи, где начинается и
где кончается область, в которой лежат **значения** (та, где `4K_30`, `Vivid`,
`MF`, `16:9`, `S-AF`...). Опиши границы адресами и покажи, что за ними уже другие
данные.

### Шаг 3 — Сгруппировать значения по смыслу
Пройди пул значений и разложи строки по командам, к которым они относятся.
Опирайся на **смысл**, а не на соседство. Ожидаемые группы (список не
исчерпывающий — ищи и другие):

| Команда | На что похожи значения |
|---|---|
| `RCISOSet` | числа: `100`, `200`, `400`, `AUTO`… |
| `RCShutterSpeedSet` | `1/100`, `SF100`, `8s`, `6.5s`, `4s`… |
| `RCFNSet` | `10.0`, `11.0`, `5.6`… (диафрагма) |
| `RCEVSet` | `-5.0`, `0.0`, `+2.0`… |
| `RCWBSet` | `Sunny`, `Cloudy`, `Shadow`, `Incand`… |
| `RCChooseColorMode` | `Vivid`, `Standard`, `Portrait`, `NaturalBW`, `HContrastBW`… |
| `RCFocusModeSet` | `S-AF`, `C-AF`, `MF` |
| `RCMeteringModeSet` | `Spot`, `CenterWeighted`… |
| `RCImageAspect` | `4:3`, `16:9`, `3:2`, `1:1` |
| `RCDriveModeSet` | `Single`, `Continuous`, `10SDelay`… |
| `RCFileFormatSet` | `RAWJ-S`, `RAWJ-M`, `RAWJ-L`… |
| `RCImageQualitySet` | `50`, `27`, `20`, `16`, `14` (мегапиксели?) |
| **`RCVideoFormatSet`** | **7 форматов — уже найдены** |
| `RCEisSwitchSet` / `RCVASwitchSet` | `On`/`Off`, `ON`/`OFF`, `0`/`1`? |

Для каждой группы: **все** строки с адресами.

### Шаг 4 — ГЛАВНОЕ: найти значения, которых нет в интерфейсе камеры
Это самая ценная часть задачи. Отдельным разделом выпиши строки, которые:
- выглядят как допустимое значение какой-то команды,
- но **не встречаются** в наших рабочих справочниках
  `yi-m1-remote-control/prot_http/const_http_cmd.py` и
  `const_http_cmd_rc_params.py` (это карта того, что мы уже умеем).

Именно так был найден 24p. Ищи внимательно: скрытые режимы качества, лишние
значения EIS/аудио, необычные варианты вроде `_LOW`/`_HIGH`, форматы файлов.

### Шаг 5 — Проверка на ложные срабатывания
Для 5–10 самых интересных находок из шага 4 проверь: точно ли это строка-значение,
а не кусок другого текста, не имя функции, не отладочное сообщение, не путь.
Покажи контекст (соседние байты) и рассуди.

```markdown
## 3. 🔍 НОВЫЕ ЗНАЧЕНИЯ, которых нет в наших справочниках
    (главный раздел — с адресами и обоснованием, к какой команде относится)
## 4. Проверка на ложные срабатывания
## 5. Готовые к отправке JSON-запросы
## 6. КРИТИКА СОБСТВЕННОГО ВЫВОДА

```

### Раздел 5 — «Готовые запросы»
Для самых перспективных новых значений — конкретные тела запросов:
```json
{"command":"<КОМАНДА>","<КЛЮЧ>":"<НОВОЕ_ЗНАЧЕНИЕ>"}
```
Ключи бери из пула в разделе 3 этого задания. Отсортируй по убыванию
уверенности. **Мы отправим их на живую камеру — поэтому не выдумывай.**

### Раздел 6 — «КРИТИКА СОБСТВЕННОГО ВЫВОДА» (обязателен)
**Минимум три конкретные причины**, по которым твоя группировка может быть
неверной. Предметно: какие строки ты отнёс к команде на слабом основании, где
мог перепутать группы, что могло быть отладочным текстом. Не можешь придумать
три — значит, недостаточно проверял.

### Правила
- **Адреса приводи полностью** (`0x006b8a50`), без сокращений.
- **Все команды/скрипты — дословно**, чтобы повторить.
- Непроверенное помечай `ГИПОТЕЗА:`. «Вероятно», «скорее всего», «должно быть»
  без этого префикса **запрещены**.
- Соседство в памяти — **не доказательство** принадлежности к команде. Если
  основание только соседство, так и пиши.
