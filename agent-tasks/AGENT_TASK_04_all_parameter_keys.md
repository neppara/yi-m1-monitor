## 2. Контекст: метод уже доказан, ты его повторяешь

Камера принимает HTTP-команды вида `{"command":"RCISOSet","ISO":"200"}`.
Обработчики устроены одинаково: в цикле перебирают ключи запроса, сравнивают
**длину** ключа с константой, затем содержимое — со строкой по указателю.

**Вчера этим методом решили `RCVideoFormatSet`**: обработчик `0x0015641c`
сравнивает длину с `10` и строку с `0x006b8416` = `"Resolution"`. Проверено на
живой камере — работает. Раньше годами перебирали неправильные имена.

**Три ключа уже известны — используй их как КАЛИБРОВКУ своего метода:**

| Команда | Обработчик | Адрес строки | Ключ | Длина |
|---|---|---|---|---|
| `RCISOSet` | `0x00155a08` | `0x006b83c8` | `ISO` | 3 |
| `RCImageAspect` | `0x00155754` | `0x006b838a` | `ImageAspect` | 11 |
| `RCVideoFormatSet` | `0x0015641c` | `0x006b8416` | `Resolution` | 10 |

**Уже найденный строковый пул ключей** (может сэкономить тебе время — многие

### Загрузка образа (проверенный рецепт — следуй точно)

Входные файлы:
```
research/YI-M1-firmware-3.2-int/3.2-int/firmware.bin.0.00008192.decompressed   # .text
research/YI-M1-firmware-3.2-int/3.2-int/firmware.bin.0.03127296.decompressed   # .rodata
```

1. Импортируй `...00008192.decompressed`: `-processor "ARM:LE:32:v5t"`
   (**без** суффикса `:default`), `-loader BinaryLoader`,
   `-loader-baseAddr 0x00002000`.
2. `...03127296.decompressed` добавь **в ТУ ЖЕ программу** как блок памяти по
   адресу `0x0043f800` через `-postScript` с Java-скриптом
   (`Memory.createInitializedBlock(".rodata", addr, ...)`).
   **НЕ отдельным `-import`** — иначе программы изолированы и xref не сойдутся.
3. Анализ включён по умолчанию (флага `-analyze` не существует). ~24 790 функций.

**Санити-чек ДО основной работы:** строка `"RCVideoFormatSet"` должна лежать по
`0x006b866c`. Нет — разметка неверна, останавливайся и пиши об этом.

### Грабли Ghidra на этом образе
Автоанализ неверно определяет границы части функций и ошибочно помечает некоторые
как "non-returning" — декомпилятор из-за этого обрезает тело. Лечится (по
возрастанию надёжности): `function.setNoReturn(false)` → снять `FlowOverride` с
CALL-инструкций (`instruction.setFlowOverride(FlowOverride.NONE)`) → **самое
надёжное**: задать тело явно через `FunctionManager.createFunction(null, entry,
body, SourceType.USER_DEFINED)`, исключив байты пула констант.

**Совет по эффективности:** собери проект **один раз** и прогони по нему все
адреса скриптом, а не пересоздавай проект под каждую команду.

### `RCDoFocus` — особый случай
Он принимает **координаты** (`Posx`/`Posy` по старым догадкам, не подтверждено).
Там может быть больше одного ключа — выпиши **все** строки, которые он сравнивает.

### Шаг 2 — Пройти команды
Для каждой: декомпилировать обработчик, найти сравнение длины ключа с константой
и адрес строки, прочитать строку. Записать в таблицу.

### Шаг 3 — Значения, где видно

### Раздел 3 — «Готовые запросы»
Для каждого найденного ключа — одна строка вида:
```json
{"command":"RCEisSwitchSet","<КЛЮЧ>":"<ЗНАЧЕНИЕ>"}
```
Мы отправим их на живую камеру. Значение бери из найденных строк; если не нашёл —
предложи правдоподобное и **пометь `ГИПОТЕЗА:`**.

### Раздел 4 — «КРИТИКА СОБСТВЕННОГО ВЫВОДА» (обязателен)
**Минимум три конкретные причины**, по которым твои результаты могут быть неверны.
Не «возможны ошибки», а предметно: какой обработчик читался хуже других, где
декомпилятор мог соврать, для каких команд ты меньше всего уверен и почему.
Не можешь придумать три — значит, недостаточно проверял.

### Правила
- Адреса — **полностью**, без сокращений.
- Все команды приводи **дословно**, чтобы повторить.
- Непроверенное помечай `ГИПОТЕЗА:`. Слова «вероятно», «скорее всего», «должно
  быть» без этого префикса **запрещены**.
- Декомпилированный код приводи **как есть**, не «причёсывая».
