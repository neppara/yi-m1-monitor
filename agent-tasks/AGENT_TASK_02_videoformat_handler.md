## 1. Задача в одном предложении

Прочитать в дизассемблере функцию-обработчик по адресу **`0x0015641c`** и выяснить,
**имя какого JSON-ключа она ищет в теле HTTP-запроса** (и какие значения принимает).

## 2. Зачем (контекст, коротко)

Камера YI M1 принимает HTTP-команды вида `{"command":"RCISOSet","ISO":"200"}`.
Команда `RCVideoFormatSet` (смена разрешения видео) **есть в таблице команд прошивки
с валидным обработчиком, но на живой камере всегда отвечает 404.**

Установлено ранее (принимай как данность, не перепроверяй):
- Единственная проверка имени команды во всей цепочке — в диспетчере `0x0015674c`,
  по таблице из 45 записей по адресу `0x006b86ac`. Второй таблицы/белого списка нет —
  это проверено побайтовым поиском указателя по всему образу.
- **Важно:** команда без обязательного параметра даёт **такой же 404**, как
  несуществующая команда. То есть 404 может означать «не угадан ключ параметра».
- Пробовали ключи `VideoFormat`, `Value`, `Mode` — все дали 404. Больше вариантов
  не перебирали.

**Отсюда рабочая гипотеза:** обработчик вызывается, но не находит нужный ключ и
возвращает ошибку, которая маппится на тот же 404. Если узнать правильное имя ключа —
командой можно будет пользоваться **без всякой перепрошивки**.

### Как загрузить (проверенный рецепт — следуй точно)

1. Импортируй **`firmware.bin.0.00008192.decompressed`**:
   `-processor "ARM:LE:32:v5t"` (без суффикса `:default` — с ним не работает),
   `-loader BinaryLoader`, `-loader-baseAddr 0x00002000`.
2. **`firmware.bin.0.03127296.decompressed` добавь в ТУ ЖЕ программу** как новый
   блок памяти по адресу **`0x0043f800`** через `-postScript` с Java-скриптом
   (`Memory.createInitializedBlock(".rodata", addr, ...)`).
   **НЕ импортируй его отдельным `-import`** — иначе это будут две изолированные
   программы без общих перекрёстных ссылок, и ничего не сойдётся.
3. Анализ включён по умолчанию (флага `-analyze` не существует). Ожидай ~24 790 функций.

### Известные грабли Ghidra на этом образе

Автоанализ **систематически неверно определяет границы функций** и помечает часть
вспомогательных функций как «non-returning», из-за чего декомпилятор обрезает тело
вызывающей функции после первого вызова. Лечится, по возрастанию надёжности:
- `function.setNoReturn(false)`;
- снять `FlowOverride` с каждой CALL-инструкции: `instruction.setFlowOverride(FlowOverride.NONE)`;
- **самый надёжный** — задать тело функции явно через
  `FunctionManager.createFunction(null, entry, body, SourceType.USER_DEFINED)`,
  исключив из диапазона байты пула констант (иначе они дизассемблируются как мусор).

**Проверка, что загрузка корректна (сделай ДО основной работы):** строка
`"RCVideoFormatSet\0"` должна лежать по адресу **`0x006b866c`**. Если её там нет —
разметка неверная, дальше идти бессмысленно, останавливайся и пиши об этом.

## 4. Что сделать

### Шаг 1 — Санити-чек разметки
Подтверди строку `RCVideoFormatSet` на `0x006b866c`. Подтверди, что по `0x006b86ac`
начинается таблица пар `{string_ptr, handler_ptr}`. Приведи в отчёте первые 3 записи
в сыром hex + их расшифровку.

### Шаг 2 — ГЛАВНОЕ: декомпилировать обработчик `0x0015641c`
Это обработчик `RCVideoFormatSet`. Приведи **полный** декомпилированный код в отчёте.

Найди в нём ответы:
1. **Какие строковые константы он использует?** Каждую — с адресом и содержимым.
   Среди них должно быть имя ожидаемого JSON-ключа.
2. **Есть ли сравнение длины строки с константой?** (например `== 11`) — длина ключа.
3. **Какие значения он принимает?** Ищи сравнения со строками вида `4K_30`, `FHD_30`,
   `2K_30`, `4K_24` и т.п. — перечисли все найденные.
4. **Какие ветки ведут к возврату ошибки?** Определи, на каком условии он выходит
   с ошибкой, если ключ не найден.

### Шаг 3 — Контрольное сравнение с ЗАВЕДОМО РАБОЧИМИ обработчиками
Это обязательно — без него выводы шага 2 недоказуемы.

Декомпилируй два обработчика команд, которые **точно работают** на живой камере:

```
RCISOSet        -> 0x00155a08     (ключ параметра точно "ISO")
RCImageAspect   -> 0x00155754
```

Для каждого определи тем же способом, какой ключ он ищет. **Сверься:** у `RCISOSet`
у тебя должен получиться ключ `ISO` — это калибровка твоего метода. Если для
`RCISOSet` метод даёт `ISO`, значит методу можно верить и для `RCVideoFormatSet`.
**Если не даёт — твой метод неверен, и результат по шагу 2 недействителен.** Так и напиши.

### Шаг 4 — Сравнить структуру
Отличается ли `0x0015641c` структурно от `0x00155a08`/`0x00155754`? Например:
- вызывает ли он функции, которых нет у рабочих;
- есть ли ранний выход по проверке состояния (режим камеры? идёт ли запись?);
- есть ли обращение к глобальной переменной-флагу.

Это может объяснить 404 иначе — не «не угадан ключ», а «обработчик отказывает по
состоянию». **Оба объяснения одинаково ценны, не подгоняй под первое.**
