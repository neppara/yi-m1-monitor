# Итоговая оценка: что реализуемо, а что нет

Дата: 2026-07-05. Это ответ по существу на изначальный вопрос сессии: **можно ли сделать для YI M1 аналог Magic Lantern, позволяющий снимать RAW-видео**, при условии "только софт, без пайки/UART/JTAG".

## Коротко

**RAW-видео в стиле Magic Lantern — нереализуемо** доступными нам средствами, и, судя по всему, нереализуемо в принципе без аппаратного вмешательства (которое мы сознательно исключили). Это не "мы не успели" — это подтверждено конкретными техническими фактами ниже, не предположениями.

Но по пути получилось реализовать реальные, рабочие вещи софтом поверх штатного API камеры — это и есть "реалистичные победы", которые пользователь просил в начале.

## Что НЕ реализуемо — и почему это доказано, а не предположено

### 1. Полнокадровое RAW-видео — физически нереализуемо на этой камере никаким софтом
Измерено на реальном DNG-файле с камеры: сенсор отдаёт 12-бит несжатый Bayer RGGB, 5200×3902 пикселей. Пересчёт: **697–871 МиБ/с** нужно писать на SD-карту для полнокадрового RAW-видео на 24–30 fps. Это выше реалистичной пропускной способности SD-карт и, вероятно, самого SD-контроллера камеры на порядок. Дело не в прошивке — дело в физике сенсора и шины. Никакой софт-хак это не обходит.

### 2. Путь "как у Canon/Fujifilm" (эксплойт через USB/PTP) — закрыт
У Canon (Check Point, DEF CON 27) и Fujifilm (проект fujihack) получение контроля над камерой шло через PTP-протокол по USB. Проверено на реальной камере: YI M1 по USB — обычная флешка (Mass Storage), PTP/MTP не отвечает ни в каком режиме подключения. Строка `MTPClassDriver` в прошивке — мёртвый код, не подключённый к активному USB-дескриптору.

### 3. Смена видео-режима/формата по Wi-Fi API — не работает и не может заработать под другим именем параметра
Декомпиляция официального приложения YI Mirrorless (первоисточник, не догадка) показала: **приложение никогда не отправляло ни одной команды удалённого управления видео**. `RCVideoFormatSet` и подобные команды физически есть в прошивке (с валидными обработчиками, подтверждено дизассемблированием в Ghidra), но не используются ни одним клиентом — ни официальным, ни каким-либо ещё. Это не "мы не угадали параметр" — такого параметра не существует ни у кого.

### 4. Перепрошивка с модификациями — заблокирована на уровне инструментария
Существующий unpack/repack-тул (`yi-mirrorless-firmware-tools`) не даёт побайтово идентичный файл при простой распаковке-запаковке без изменений. Прошивать модифицированный файл в текущем состоянии — реальный риск окирпичить камеру. Без решения этой проблемы любая модификация прошивки (даже безобидная) не готова к безопасной заливке.

### 5. Собственный код-инъекшн в прошивку (настоящий путь "написать свой Magic Lantern") — теоретически возможен, но это отдельный многомесячный проект
Это то, что реально сделала команда Magic Lantern для Canon: нашли RAW-буфер живого видео в памяти, разобрались с ISP-конвейером, написали ARM-код, который перехватывает поток до сжатия в H.264 и пишет сырые кадры на карту. Для YI M1 это потребовало бы:
- Полного дизассемблирования конвейера обработки изображения (ISP) в прошивке — мы прошли только диспетчер HTTP-команд, это малая часть кода;
- Понимания, где в памяти лежит сырой RAW-буфер во время видеосъёмки (если он вообще доступен в этот момент, а не сбрасывается сразу в аппаратный энкодер);
- Написания и внедрения нового ARM-кода в прошивку в обход штатного конвейера;
- Решения проблемы безопасной перепрошивки (пункт 4) или поиска альтернативного способа загрузки кода без полной перезаписи прошивки (такого способа сейчас не найдено — PTP-путь закрыт, других механизмов загрузки неподписанного кода не обнаружено).

Это реализуемо только как отдельный, самостоятельный исследовательский проект на месяцы работы опытного embedded-реверсера — не как продолжение текущей сессии.

## Что РЕАЛИЗОВАНО и работает прямо сейчас

- **Рабочий CLI для удалённого управления камерой** (`yi-m1-remote-control/`) — BLE-пейринг напрямую с компьютера (без официального приложения) + Wi-Fi HTTP API: ISO, баланс белого, выдержка, диафрагма, EV, режим экспозиции (P/A/S/M), качество/пропорции/формат снимка (включая RAW), автофокус по координатам на экране, спуск затвора.
- **Удалённый старт/стоп видеозаписи по Wi-Fi** — не задокументировано нигде, найдено и подтверждено нами (записанный файл на карте, реальные параметры 1920×1080/30fps H.264 через `ffprobe`).
- **Полная и исправленная карта HTTP-командного интерфейса камеры** — 45 команд с адресами обработчиков (Ghidra), исправляет ошибки в адресах из первоначального ручного анализа.
- **Полная характеристика RAW-формата стилл-фото** (12-бит, Bayer RGGB, реальные размеры сенсора, уровни чёрного/белого) — пригодится для любой будущей работы с файлами этой камеры.
- **Подтверждённая идентификация платформы** — Xacti Corporation, тот же ODM, что делал линейку Fujifilm X-A в 2016–2017.

## Рекомендация

Если исходная цель — именно RAW-видео на этой конкретной камере software-only — вопрос закрыт отрицательно, с доказательствами, а не с "не получилось попробовать". Если интересно продолжать в сторону, где реально есть прогресс — это доработка инструмента удалённого управления (интервалометр, брекетинг, просмотр/скачивание файлов) или, для тех, кто готов вложить месяцы в глубокий embedded-реверс без гарантии результата, — code injection в ISP-конвейер прошивки как отдельный проект.
