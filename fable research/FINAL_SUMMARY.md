# YI M1 — итоги исследования и разработки

Дата свода: 2026-07-24. Репозиторий: **https://github.com/echeetah/yi-m1-monitor** (MIT).

Это верхнеуровневый свод: что сделано, что доказано, что закрыто и что осталось.
Технические детали — в отдельных документах `fable research/`, ссылки по тексту.

---

## 1. Что получилось (работает и в приложениях)

Два независимых приложения на реверс-инженерном протоколе камеры:
**macOS** (Python/PySide6) и **iOS** (Swift/SwiftUI, ядро `YiM1Core`, 53 теста).

Реализовано: live view по Wi-Fi, спуск/запись, полная панель настроек, файловый
браузер, фокус-пикинг (свой Sobel), направляющие/кроп, поворот, таймер записи,
почти-непрерывная запись с автоперезапуском.

### Разблокировано реверсом (нет в меню камеры, не умело официальное приложение)

Всё подтверждено на живой камере и, где применимо, доказано `ffprobe` по файлам.
Детали: `rcvideoformatset-solved.md`, `hidden-value-candidates.md`.

| Возможность | Как |
|---|---|
| **Смена видеоформата по Wi-Fi** | `RCVideoFormatSet`, ключ **`Resolution`** (не `VideoFormat`) |
| **24p** (4K и FHD) | `4K_24`, `FHD_24` — нет ни в одном меню камеры |
| **720p** 60/30/24 | `720P_60/30/24` |
| **Слоу-моушен 240 fps** | `VGA_240` — камера снимает ~240 к/с и сама конформит в 30 → 8× замедление |
| **Стабилизация вкл/выкл** | `RCEisSwitchSet`, ключ `Operate`, значения `ON`/`OFF` (ЗАГЛАВНЫЕ) |
| **Звук / шумодав / громкость микрофона** | `RCVASwitchSet`, `RCVANoiseReduceSet` (`Operate`), `RCVAVolSet` (`Vol`) |
| Короткие выдержки | `1/8000s`, `1/6400s`, `1/5000s` |

Все четыре «звуко-видео» команды и `RCVideoFormatSet` годами числились у всех
(включая нас) как «404, не подключены». На деле всё это время им слали **неверное
имя параметра**.

### Ключевой методологический урок проекта
**Отрицательный результат живого перебора — не доказательство невозможности.**
Команда без правильного параметра даёт тот же 404, что несуществующая. Статический
анализ прошивки дал точные имена там, где перебор годами давал ложное «нельзя».

## 2. Что закрыто обоснованно (не «не смогли», а «этого нет»)

| Направление | Вывод | Где доказано |
|---|---|---|
| **RAW-видео** | невозможно: запись ~700–870 МиБ/с, физика шины | `final-assessment.md` |
| **Битрейт / профиль H.264** | параметров нет в основном образе — они в прошивке субпроцессора Xacti, которой в `firmware.bin` нет | `firmware-memory-map.md` |
| **Родной фокус-пикинг** | камера гасит его на время Wi-Fi-сессии; в поток не отдаётся | `hidden-value-candidates.md` |
| **Прошивка объектива 0.0** | объектив электронно мёртв (`lenType=""`, `LensStatus=0`); шить нечего | `vendor-outreach-and-hardware-status.md` |
| **`UploadML` как канал записи файла** | не пишет файл: кладёт 15-байтовое имя в RAM. Канала записи произвольного файла по Wi-Fi нет | `AGENT_RESULT_11` |
| **`AdobeRGB` / гистограмма / звуки по Wi-Fi** | в прошивке есть, но команд/ключей для них нет — только меню камеры | — |
| **Экспо-коррекция предпросмотра** | предпросмотр (`THROUGH`) авто-экспонируется отдельно от записи (`MOVIE`); данных для честной коррекции нет, эталон экспозиции — только тестовая запись | — |

## 3. Про железо этого экземпляра (не софт)

- **Затвор механически неисправен:** фото на выдержках короче ~1/13 дают одинаковый
  результат — шторки не успевают. Видео (электронный затвор) работает во всём
  диапазоне — это и есть доказательство, что дело в механике, а не в ПО.
- **Китовый объектив электронно не опознаётся** — подтверждено холодным стартом.
  Отсюда `0.0`, неработающий апдейт объектива и то, что `RCFNSet` глотает любой
  Fnumber (пределы диафрагмы нулевые).

## 4. Про прошивку

- Изучен **HTTP-интерфейс целиком**: 45 команд, 18 ключей, 128 таблиц значений,
  13 видеорежимов, диспетчер, цепочка от сокета до обработчика. Это вся поверхность
  удалённого управления — того, ради чего проект начинался, неизученного не осталось.
- По объёму это ~0.1% функций `.text` — остальное (ISP, автофокус, драйверы,
  интерфейс) через Wi-Fi недостижимо в принципе и лежит за стеной, которую мы
  сознательно не ломаем (без UART/JTAG).
- **Механизм сервисных `.SDK`-файлов** разобран (цикл `0xab8cc`, геттер флагов
  `0xab97c`, раскладка индексов). Файлы кладутся на SD-карту, читаются при старте.
  `WIFIDUMP.SDK` включает подробный лог Wi-Fi, но **в консоль/UART**, не в файл —
  по Wi-Fi недостижимо. Живьём ни один `.SDK` не проверялся.
- **Перепрошивка невозможна безопасно:** инструмент определяет границы подсекций
  эвристикой, а как их находит реальный загрузчик — неизвестно. После вывода из
  п.2 (в основном образе менять по сути нечего) ценность направления мала.

## 5. Инфраструктура, наработанная по пути

- `probe_connect.py` — автоподключение всех probe-скриптов (BLE-пейринг с 5
  попытками, т.к. камера рекламируется через раз; присоединение к Wi-Fi;
  восстановление домашней сети).
- Набор probe-скриптов: `probe_resolution_key`, `probe_hidden_values`,
  `probe_clips_and_lens`, `probe_unknown_commands`, `probe_service_mode`,
  `probe_ble_check`.
- `firmware-memory-map.md` — карта секций и правильная загрузка в Ghidra (все ТРИ
  секции, включая `.data`, без которой ссылки не строятся).
- 11 брифов для саб-агента + отчёты в `agent-tasks/`.

## 6. Что стоило сделать / осталось недоделанным

Честный список, а не «всё идеально».

1. **Кроп для 720p и VGA_240 не измерен.** Приложение позволяет выбрать эти режимы,
   но рамка кропа показывает полный кадр — почти наверняка неверно (у них своя
   геометрия считывания). Кропы 2K/FHD/4K измерены и применяются верно. Нужно снять
   реальный кроп для новых режимов (тот же метод template-matching, что и раньше).
2. **Диафрагмы `2.9/3.6/6.4/8.4` добавлены на слабом доказательстве.** `RCFNSet`
   принял и мусорное `99.9` (объектив мёртв). На камере с рабочим объективом стоит
   перепроверить, что они реально применяются, иначе — убрать.
3. **Автоперезапуск для `FHD_60` не выверен по времени.** 60p имеет вдвое больший
   битрейт, лимит 4 ГБ может наступить раньше таймера 29:55. Нужен один реальный
   замер клипа 60p до естественного конца; пока страхует fps-детектор.
4. **`.SDK`-режимы не проверены живьём.** Механизм разобран, но ни один файл не
   пробовался. `NOSLEEP` безопасен по коду; безопасность 6 режимов — `НЕИЗВЕСТНО`.
   Тест сна готов (`probe_service_mode.py --sleep-test`), не запускался.
5. **Скриншоты/GIF в README нет.** Для портфолио сильно повышают отдачу; разделы
   под них есть, картинок нет.
6. **Затвор и объектив** — user-side, не софт, но остаются главными ограничениями
   реального использования камеры.

## 7. Открытые ниточки (если возвращаться)

- **Файловый слой прошивки** (функции записи/создания файла, `0x1a...`): зная их
  адреса, любую цепочку можно механически проверять на «доходит ли до записи» —
  это закрыло бы вердикты по безопасности `.SDK` без гадания.
- **Прошивка субпроцессора Xacti** — где лежит (отдельный раздел флеша? IPC при
  старте?). Только там параметры кодека. Требует аппаратного доступа.
- **Трассировка `BT_LENS_INIT`** — встроенное профилирование инициализации
  объектива. Если найти способ достать эти логи, можно увидеть точку отказа
  китового объектива. `WIFIDUMP` их в файл не пишет — нужен другой канал.
