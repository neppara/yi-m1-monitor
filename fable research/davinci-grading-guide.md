# YI M1 → DaVinci Resolve: грейд и цвет

Практическая памятка под конкретную камеру. Всё привязано к тому, что **измерено**
`ffprobe` на реальных файлах с YI M1, а не к общим советам.

---

## Что мы реально снимаем (константы, не изменить)

```
H.264 Constrained Baseline · 8 бит · 4:2:0 · yuvj420p (FULL range) · ~16 Мбит/с (фикс)
color_primaries = smpte170m (Rec.601)   ← тег спорный
color_matrix    = smpte170m (Rec.601)   ← тег спорный
color_transfer  = bt709                  ← не совпадает с primaries
```

Замеренный битрейт FHD: **FHD_24 ≈ 15.9 Мбит/с**, **FHD_30 ≈ 15.5 Мбит/с** — почти
одинаково (битрейт по разрешению, не по fps; у 24p чуть больше бит на кадр).

**Это НЕ лог и НЕ RAW.** Готовая display-referred картинка в почти-Rec.709, 8 бит,
малый запас на грейд. Обращаться как с «продвинутым JPEG», а не как с логом.
Профиль/битрейт наружу не меняются (зашиты в субпроцессоре Xacti — см.
`firmware-memory-map.md`), так что качество берётся на съёмке.

---

## 1. Правильный приём (спорные места — чинить ДО грейда)

### Data Levels → Full (не Video)
`yuvj420p`: буква `j` = **full range 0–255**. Если Resolve прочитает как Video
(16–235) — молочные подтянутые чёрные, неверные уровни, тени грязнят сильнее.
→ Клик по клипу → **Clip Attributes → Data Levels → Full**. Проверь по вейвформе:
чёрное садится в 0, белое доходит до верха. Частый источник «пурпура в тенях».

### Матрица 601 → ставить 709
Камера пометила Rec.601, для HD стандарт — **709** (энкодер влепил дефолт). Неверная
матрица = сдвиг насыщенных цветов (кожа, насыщенные участки).
→ Input Color Space = **Rec.709**, не 601. Сверить глазом на коже.

---

## 2. Управление цветом: DaVinci Wide Gamut — поможет?

**Да для математики грейда, нет для динамического диапазона.**
DWG даёт широкий гамут и лог-подобную кривую → меньше hue-twist, аккуратнее
переходы, меньше артефактов при растягивании. НО источник 8 бит 709 — перевод в DWG
**не создаёт данных**, широты и чистоты теней не прибавит. Включать стоит («не наврежу
лишним»), чуда не ждать.

### Рекомендованный RCM (простой путь)
Project Settings → Color Management:
- **Color Science:** DaVinci YRGB Color Managed
- **Input Color Space:** Rec.709 Gamma 2.4 (задать и на клипах: правый клик → Input Color Space)
- **Timeline / Working:** DaVinci WG / Intermediate
- **Output:** Rec.709 Gamma 2.4

Альтернатива для контроля: обычный YRGB + нода **CST** (Rec.709→DWG в начале,
DWG→Rec.709 в конце).
Гамма: если 2.4 слишком тёмная/контрастная — пробуй 2.2 (на full-range 8-бит бывает).

---

## 3. Порядок нод (для 8 бит критично)

```
1. Шумодав (ПЕРВЫМ)  →  2. Input/CST  →  3. Баланс/экспозиция
→  4. Фикс пурпура в тенях  →  5. Look/насыщенность  →  6. Зерно/дизер
```

**Шумодав — до всего.** На 8 битах Temporal NR (Resolve **Studio**) — самый большой
выигрыш качества; подъём после чистого сигнала даёт вдвое меньше грязи.
В бесплатной версии NR нет — ощутимое ограничение именно для этого материала.

---

## 4. Точечные фиксы

### Пурпурные (magenta) тени
Две причины накладываются: **IR-загрязнение от дешёвого ND** (каст в чёрном/тенях) и
**8-бит 4:2:0 при 16 Мбит/с** (цветной шум при подъёме, кривится в magenta).
1. Root-фикс IR — **IR-cut ND** (Hoya/Breakthrough/PolarPro с IR-коррекцией). Неравномерный
   IR-каст в посте чисто не убрать.
2. Curves → **Lum vs Sat**, опустить тёмный конец — обесцветить глубокие тени
   (они и не должны держать насыщенность). Убирает magenta-шум почти бесплатно.
3. **Offset** в тенях чуть в зелёный (противоположность magenta) — осторожно, глобально.
4. Точечно: luma-qualifier по тёмным → Hue vs Hue увести magenta / десатурировать.

### Проверка «IR или кодек»
Снять ту же сцену **без ND**: пурпур ушёл → виноват фильтр (IR). Пурпур при подъёме
хорошо экспонированного кадра остаётся → это кодек/8 бит.

### Бандинг
Resolve внутри 32-bit float — промежуточные операции не банят; банит исходная
квантизация и вывод. → **тонкое зерно** (Studio: Film Grain / оверлей) разбивает полосы
+ **дизер на выводе**.

### Резкость
Источник мягкий + низкий битрейт; шарп усиливает блоки компрессии. Только лёгкий,
после NR.

---

## 5. Вывод

- **Не пережимать в ещё один low-bitrate 8-бит.** Мастер — **ProRes 422** (или
  H.264/H.265 высокого битрейта). Второе поколение 8-бит 4:2:0 добьёт тени.
- Доставка — Rec.709 Gamma 2.4, дизер включён.

---

## Итог

**Максимум качества:** (1) Full data levels + Input Rec.709; (2) RCM с DWG — чище
математика, не чудо; (3) NR первым (нужен Studio); (4) обесцветить тени + зерно/дизер;
(5) мастер в ProRes.

**Но 80% — на съёмке:** IR-cut ND и экспозиция «вправо» (ETTR в меру). На таком кодеке
грейд — шлифовка, спасать в посте почти нечего.

---

## Съёмочный чек-лист (чтобы кодеку было легче)

- Экспонировать **правее** — не вытягивать тени в посте (там на 8 битах почти пусто,
  и там же magenta).
- **IR-cut ND**, не дешёвый.
- Меньше мелкого хаотичного движения в кадре (листва, вода, дождь) — оно быстрее всего
  съедает фиксированные 16 Мбит/с и вылезает блоками.
- Правильная экспозиция важнее обычного: запас качества у кодека маленький.
- Помнить: **звук** — `VASwitch=ON`, громкость микрофона повыше (камера по умолчанию
  `VAVol=2`, это тихо); **слоу-мо VGA_240 пишется без звука** by design.
