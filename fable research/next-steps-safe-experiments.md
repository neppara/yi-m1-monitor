# Конкретный план: что можно попробовать прямо сейчас

Всё ниже — только софт со стороны компьютера + штатный USB-кабель / Wi-Fi. Никакой пайки, UART, JTAG, вскрытия корпуса. Ничего не прошивается в камеру (repack прошивки всё ещё не побайтово идентичен — см. `../research/yi-m1-raw-video-feasibility.md`, флэшить нельзя).

Порядок — от абсолютно безопасного к чуть более рискованному (но всё ещё программному).

## 1. ~~Проверить, отдаёт ли камера себя по USB как PTP/MTP-устройство~~ — сделано, результат отрицательный

Проверено 2026-07-02 на реальной камере пользователя: по USB-кабелю YI M1 всегда представляется как **USB Mass Storage** (`bInterfaceClass=8`, `bInterfaceSubClass=6`, `bInterfaceProtocol=0x50`), карта памяти монтируется как обычный диск. Выбора режима подключения на экране камеры не было. В прошивке нет строки-переключателя режима USB, доступной без UART. Подробности и что это значит — в обновлённом `ptp-mtp-attack-surface.md`.

**Вывод:** ветка "PTP-эксплойт по USB как у Check Point/fujihack" для этой камеры в её текущем виде закрыта. Не тратить время на `gphoto2`/`ptpy` против стандартного USB-подключения — оно ничего не даст, камера там не PTP-респондер. Переходим сразу к следующему пункту.

## 2. Догнать карту HTTP API с помощью bullbin/xiaoyi_m1_re_liveview (сейчас — приоритет №1)

Вместо того чтобы вручную гадать параметры по строкам из прошивки:

1. Клонировать https://github.com/bullbin/xiaoyi_m1_re_liveview.
2. Открыть `const_http_cmd.py` и `const_http_cmd_rc_params.py` — там уже расписаны команды и их параметры из официального приложения.
3. Сопрячь камеру через официальное приложение YI Mirrorless один раз (для получения Wi-Fi пароля — 8-значный PIN, как описано в README `yi-mirrorless-firmware-tools` и в проекте bullbin), затем подключить ноутбук к тому же Wi-Fi камеры вместо телефона.
4. Погонять `RCVideoFormatSet` с разными значениями через `curl` или `debug_html.py` из репозитория bullbin, проверяя, не включаются ли скрытые режимы `4K_24` / `4K_30_LOW`, чьи строки уже найдены в прошивке (`../research/yi-m1-raw-video-feasibility.md`, раздел "Video and RAW related strings").

Риск: нулевой, это штатный протокол управления, тот же, что использует официальное приложение.

## 3. Снять реальный DNG и разобрать его

Камера уже умеет снимать RAW (DNG) в фотографии — это не хак, это штатная функция:

1. Снять несколько кадров в RAW/DNG в разных условиях (разный ISO, разная выдержка).
2. Разобрать через `exiftool` и/или `dcraw -v -i -v <file>.dng`, чтобы зафиксировать:
   - паттерн Байера,
   - реальную битность (12-бит согласно строкам в прошивке — подтвердить эмпирически),
   - уровни чёрного/белого,
   - точное разрешение сенсора в RAW относительно заявленных 5184×3888.
3. Сложить эти цифры рядом с таблицей пропускной способности в `../research` (раздел "RAW bandwidth math") — это единственный кусок, который сейчас основан на паспортных, а не измеренных характеристиках.

Риск: нулевой, обычная съёмка.

## Что дальше, раз USB — это просто флешка

Раз PTP-канал по USB не подтвердился, самые многообещающие оставшиеся направления — это шаг 2 (HTTP API по Wi-Fi, ещё живой и подтверждённый канал управления) и шаг 3 (эмпирика по DNG). Дизассемблирование прошивки ради поиска RAW-буфера (Phase 0-3 из `../research/yi-m1-raw-video-feasibility.md`) остаётся единственным путём к самому RAW-видео, но это уже не "быстрая победа", а полноценный исследовательский проект без готовых аналогов извне (см. вывод в `related-projects-and-community.md`).
