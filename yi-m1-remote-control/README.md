# yi-m1-remote-control

Практичный интерактивный CLI для удалённого управления камерой YI M1 по Bluetooth LE (пейринг) + Wi-Fi (HTTP API). Собран на основе библиотеки протокола из [bullbin/xiaoyi_m1_re_liveview](https://github.com/bullbin/xiaoyi_m1_re_liveview) (см. `LICENSE_upstream_bullbin`), с исправлениями надёжности BLE на macOS и набором команд, подтверждённых работающими вживую на реальной камере (прошивка 3.2-int) — см. `../fable research/live-testing-findings.md`.

## Что умеет

- Подключается к камере по BLE прямо с компьютера, без официального приложения на телефоне.
- Получает SSID/пароль Wi-Fi сети камеры.
- После переключения Wi-Fi — интерактивное меню: статус камеры, ISO, баланс белого, выдержка, диафрагма, EV, режим экспозиции (P/A/S/M), качество/формат изображения (включая RAW), режим серийной съёмки, автофокус, спуск затвора, **старт/стоп видеозаписи**.

## Что НЕ умеет (и почему)

Смена формата/разрешения видео (`RCVideoFormatSet`) и переключатели видео-настроек (`RCVASwitchSet`, `RCEisSwitchSet`, `RCVANoiseReduceSet`) — не реализованы, потому что **они не работают**: несмотря на то что эти команды присутствуют в прошивке с валидными обработчиками (подтверждено дизассемблированием, см. `../fable research/ghidra-disassembly-findings.md`), HTTP-сервер камеры отвечает на них 404 Not Found. Подробности — там же.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Запуск

**Важно**: запускать из обычного Terminal.app (или другого полноценного терминального приложения), а не из автоматизированной/песочницы-сессии — иначе macOS не сможет выдать разрешение на Bluetooth (процесс без подписанного app-бандла получает `SIGABRT` вместо диалога с запросом разрешения).

```bash
python3 yi_m1_remote.py
```

1. Убедиться, что камера включена и рядом.
2. Скрипт запросит пейринг по BLE — подтвердить "Accept" на экране камеры.
3. Получить SSID/пароль, переключить Wi-Fi компьютера на сеть камеры, нажать Enter.
4. Пользоваться интерактивным меню.
5. При выходе (пункт 0) корректно завершает сессию удалённого управления (`RCStopRemoteCtl`).

## Известные ограничения BLE на macOS (уже исправлено в этом инструменте)

- Сканирование и подключение в двух разных `asyncio.run()`-вызовах на macOS ненадёжно (`CBCentralManager` не всегда видит устройство, найденное предыдущим сканированием) — здесь сканирование и подключение объединены в одну сессию.
- Фильтр `service_uuids` в `BleakScanner` не всегда надёжен — здесь дополнительно проверяется, что нужный UUID реально есть в рекламных данных найденного устройства.
- Прошивка камеры не отдаёт стандартную GATT-характеристику "Device Name" — чтение этого (и manufacturer/model) поля обёрнуто в `try/except`, так как эти поля всё равно не используются в логике пейринга.

## Структура

- `yi_m1_remote.py` — интерактивный CLI (первая версия инструмента, меню в терминале).
- `app/` — **GUI-приложение "YI M1 Monitor"** (PySide6), см. `app/ARCHITECTURE.md` — актуальный основной инструмент, разрабатывается вместо/поверх CLI.
- `prot_ble/` — BLE-протокол пейринга (форк bullbin, с патчами надёжности).
- `prot_http/` — HTTP-команды управления (форк bullbin, дополнено `VideoRecordingStart`/`Stop`).
- `probe_*.py` — одноразовые скрипты для проверки гипотез во время исследования (не часть продукта, оставлены для истории — см. `../fable research/live-testing-findings.md`).

## GUI-приложение (`app/`)

Desktop-приложение на PySide6: live view с камеры (сетка третей + примерная граница видео-кропа как оверлеи), кнопки Connect/Disconnect и REC/STOP, статус (батарея/кадры). Подробная архитектура, статус реализации и известные грабли — в **[app/ARCHITECTURE.md](app/ARCHITECTURE.md)**. Начните с этого файла, если продолжаете разработку.

Запуск (тоже только из Terminal.app, причина та же — разрешение Bluetooth):
```bash
source venv/bin/activate
python3 app/main.py
```
